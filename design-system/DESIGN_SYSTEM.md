# Game Room — дизайн-система «Эфир»

Визуальная система голосовой комнаты (октябрь 2026). Этот документ — контракт
для всех, кто пишет интерфейс: прочитайте целиком и делайте одинаково.

| Что | Где |
|---|---|
| Токены (цвет, шрифт, форма, движение) | `design-system/tokens.css` (переменные `--gr-*`) |
| Мост в Tailwind (`bg-canvas`, `text-ink`…) и база `[data-ui]` | `src/app/globals.css` |
| Примитивы | `src/components/ui/` — импорт из `@/components/ui` |
| Витрина всех примитивов | `/design` (в dev; в проде только с `NEXT_PUBLIC_SHOW_DESIGN=1`) |
| Макеты экранов на моковых данных | `/design/<экран>`, исходники — `src/app/design/_mocks/` |
| Знак и логотип | `public/brand/*.svg`, компонент `Logo` |
| Маскот Румик, рисовалка и декор витрины (бренд-слой) | §8; компоненты `Rumik`, `RumikAvatar`, рисовалка `src/components/rumik/`, декор `src/components/marketing/decor/`; каталог `/design/rumik`, рисовалка `/design/editor` |

Своих глобальных классов (`.btn`, `.panel`…) у интерфейса нет: всё — примитивы и
утилиты Tailwind на токенах.

## 1. Концепция

**«Ночной эфир у круглого стола».** Компания друзей вечером садится за один стол:
кто-то говорит, кто-то показывает экран, все видят друг друга. Интерфейс —
графитовая комната с приглушённым светом: тихий, тёмный, не спорит с игрой.
Цвет в нём приносят **люди** (у каждого свой цвет аватара или свой рисунок) и **события**
(кто говорит, кто в эфире, что сломалось). Декоративного цвета нет вообще
(кроме бренд-слоя витрины, §8).

Характер — в композиции и деталях, а не в непонятном управлении: участники
стоят **вокруг стола** — каждый своим Румиком, которого сам раскрасил (§8); у
говорящего загорается лаймовая обводка цвета «эфира» (`signal`) и значок у
головы (у кружка-аватара — кольцо, которое расходится волной в такт голосу); полоса уровня
микрофона сделана как прибор — сегменты, порог прямо на полосе; название
комнаты и крупные заголовки набраны широким гротеском Unbounded. Управление —
привычное по Discord и Google Meet: круглые кнопки дока, красная заливка = «вас
не слышно», меню по клику на человека.

Что взяли у других и почему:

| Откуда | Что | Зачем |
|---|---|---|
| Discord | кольцо «говорит», меню по клику на участника, список в узком окне | привычно сразу |
| Google Meet | лобби с проверкой микрофона, док из круглых кнопок, красный = выключено, окно поверх всех (Document PiP), «Вы вышли · Вернуться» | понятные состояния, вход в один клик |
| Telegram / Clubhouse | крупные аватары-кружки, «волна» вокруг говорящего | голос виден боковым зрением |
| Slack huddle | компактное окно «кто говорит + две кнопки» | мини-комната поверх игры |
| Linear / Vercel | графит, «чернильная» главная кнопка, волосяные линии | спокойно часами |

## 2. Принципы

1. **Цвет = событие.** Каждый цвет закреплён за одним смыслом (таблица в §3).
   Если элемент цветной — он что-то сообщает. Хотите выделить — размером,
   весом, расположением, а не цветом. Исключение: маскот, рисунки людей на
   нём и оформление витрины (§8).
2. **Люди — главные.** Аватар, имя и состояние голоса — самые заметные вещи на
   экране. Всё остальное отступает.
3. **В покое ничего не движется.** Комната открыта рядом с игрой и не отнимает
   FPS: нет `backdrop-filter`, нет blur и тяжёлых теней поверх видео, нет
   бесконечных анимаций, нет постоянных таймеров и `requestAnimationFrame`.
   Анимации — только `transform`/`opacity`, короткие, с `prefers-reduced-motion`.
   Библиотек анимации не подключаем: хватает CSS. Оговорки (§8): на витрине
   «стена» по краям сдвигается при прокрутке (параллакс), в рисовалке глаза
   Румика следят за курсором, в комнате Румик отвечает на реакцию жестом на
   2 с. Движение только от пользователя или события, в покое всё неподвижно,
   при «меньше движения» стоит.
4. **Удобство важнее необычности.** Кнопки, меню и диалоги ведут себя как
   везде. Необычное — только в композиции (стол), типографике и деталях.
5. **Узкое окно — главный сценарий.** 360–420 px сбоку от игры. Каждый экран
   проверяется на 390×844 так же строго, как на 1440×900.
6. **Клавиатура и скринридер — по умолчанию.** Видимый фокус, Esc, стрелки,
   подписи у иконок, контраст AA. Это свойства примитивов — не ломайте их.
7. **Тексты — по-русски и просто.** Без канцелярита и «украшательств» тире.
   Ник не склоняем: «**Ника** теперь в комнате», а не «Вошла Ника» и не
   «Выгнать Нику?».

## 3. Токены

Компоненты пишутся **только** Tailwind-классами из этой таблицы. Сырые hex и
`dark:`-варианты запрещены. Единственное исключение — краска рисунка в
рисовалке: это данные человека, а не цвет интерфейса (§8 «Рисовалка»).

### Цвет

| Класс | Смысл | Где |
|---|---|---|
| `bg-canvas` | фон приложения | корень экрана |
| `bg-raised` | приподнятое | карточки, док, панель чата |
| `bg-overlay` | всплывающее | меню, поповеры, диалоги, тосты, тултипы |
| `bg-sunken` | утопленное | поля ввода, «колодцы» |
| `bg-video` | поле у видео | сцена |
| `bg-wash-1/2/3` | полупрозрачная заливка: тихо / наведение / нажато | строки, мягкие кнопки |
| `border-line` / `-line-strong` / `-line-control` | волосяная / рамка контрола / рамка при наведении | |
| `text-ink` / `-ink-2` / `-ink-3` | текст основной / вторичный / подсказки (все AA) | |
| `text-ink-faint` | выключенное, декор (не AA — не для смысла) | |
| `bg-ink text-inverse` | **главная кнопка** («чернильная») | одна на экран |
| `signal` (+`-ink`, `-wash`, `on-signal`) | **передаёт**: говорит, рация в эфире, идёт показ экрана, «Эфир» | кольцо, бейдж |
| `alert` (+`-ink`, `-wash`, `on-alert`) | **не слышно / опасно**: мьют, звук выкл, ошибка, кик/бан | заливка кнопки, значок |
| `caution` (+`-ink`, `-wash`, `on-caution`) | **внимание**: переподключение, слабая связь, предупреждения | баннер, плашка |
| `crown` | только корона хоста (в бренд-слое — ещё корона на Румике, §8) | |
| `link` | ссылки в чате | |
| `focus` | кольцо фокуса клавиатуры (ставится само) | |
| `--gr-rumik-eye` / `-white` / `-sticker` | глаз-кольцо на тёмной плашке / некрашеный Румик / белый край наклейки; одинаковы в обеих темах | **только** `Rumik` (§8), через `var(…)` |

Палитра аватаров — `--gr-avatar-0…9`: 10 оттенков одной светлоты, жёлто-зелёный
пропущен (он у `signal`). Цвет считают `assignAvatarColors(ники по joinedAt)` —
в комнате без повторов, у всех клиентов одинаково — или `avatarColorIndex(ник)`
для одного человека. Имя автора в чате — тем же цветом: `style={{ color:
avatarColorVar(i) }}`.

### Типографика

Шрифты подключены в `layout.tsx`: **Unbounded** (`font-brand`) и **Onest**
(`font-body`, стоит на `UiRoot` по умолчанию). `font-code` — системный
моноширинный, только для техничных цифр («Качество показа» на сцене).

| Класс | Размер | Для чего | Шрифт |
|---|---|---|---|
| `text-hero` | 40→72 | заголовок лендинга | `font-brand` |
| `text-display` | 32/38 | название комнаты в лобби, крупные состояния | `font-brand` |
| `text-heading` | 22/28 | заголовки экранов и пустых состояний | `font-brand` |
| `text-title` | 17/24 · 600 | заголовки панелей, диалогов, секций | Onest |
| `text-body-lg` | 15/22 | сообщения чата, текст в полях | Onest |
| `text-body` | 14/20 | основной текст интерфейса | Onest |
| `text-label` | 13/18 | подписи полей, вторичный текст | Onest |
| `text-caption` | 12/16 | подсказки, время, «182 мс» | Onest |
| `text-micro` | 11/14 | счётчики, keycap | Onest 600 |

Цифры, которые меняются (мс, %, дБ, счётчики) — `tabular-nums`. Название
комнаты в шапке: `font-brand text-[17px] font-semibold` (15px на узком).
Код комнаты — `font-brand` с разрядкой `tracking-[0.16em]`. Текст из данных
(название комнаты) в крупных заголовках — через `glueShortWords()`: неразрывный
пробел после «в», «с», «и», «для»…, чтобы предлог не висел в конце строки (то же
в OG-картинках).

### Форма

Правило: **внутренний радиус = внешний − отступ** (концентрические углы).

| Класс | Радиус | Для чего |
|---|---|---|
| `rounded-key` | 6 | keycap, мелкие метки |
| `rounded-item` | 10 | пункты меню, сегменты, мелкие кнопки внутри контейнера |
| `rounded-control` | 12 | кнопки с текстом, поля, select |
| `rounded-card` | 16 | карточки, поповеры, тосты, строки списков |
| `rounded-panel` | 24 | диалоги, сцена, большие панели |
| `rounded-full` | — | аватары, док и его кнопки, переключатели, бейджи |

Встроенные `rounded-sm/md/lg` **не использовать** — у системы своя шкала радиусов.

Отступы — стандартная шкала Tailwind (шаг 4px): внутри контролов 8–12, внутри
карточек 20–24, между секциями 24–32.

### Тени, слои, движение

- Тени: `shadow-raised` (карточки), `shadow-float` (меню, тосты), `shadow-dialog`
  (диалоги). Элементам, которые **постоянно** лежат поверх видео, теней не даём.
- Диалоги, меню, поповеры, тултипы — в **top layer** браузера (нативные
  `<dialog>` и `popover`): поверх всего без z-index. Остальное — шкала
  `--gr-z-*`: шапка 10, кнопки на видео 20, док 30, выезжающий чат 40, тосты 70.
- Кривые: `ease-swift` (вход, отклик — по умолчанию), `ease-glide` (перемещение по
  экрану), `ease-drawer` (выезжающие панели). Длительности: нажатие 100,
  наведение и тултип 140, меню 180, диалог и тост 240 мс. Больше 300 мс — нет.
- Появление: CSS `@starting-style` (Tailwind `starting:`), а не JS. Закрытие —
  мгновенное или быстрее появления.
- Внимание: в Tailwind 4 `scale-*`/`translate-*` пишут свойства `scale`/`translate`,
  а не `transform`. В `transition-[…]` перечисляйте `scale`, `translate`.
- `prefers-reduced-motion`: глобальное правило гасит длительности; масштабы и
  сдвиги прячем за `motion-safe:`.

### Темы

Тёмная — по умолчанию. Светлая готова в токенах: `data-theme="light"` на `<html>`
или `<UiRoot theme="light">`, и всё перекрашивается само (проверено на витрине и
`/design/room?theme=light`). Переключателя темы в интерфейсе **нет**. Условие,
чтобы светлая работала одной строкой: ни одного `dark:`, `light:` или hex в
компонентах.

## 4. Примитивы

Импорт: `import { Button, IconButton, … } from "@/components/ui"`. Все интерактивные
примитивы — клиентские; `UiRoot`, `Card`, `Badge`, `Kbd`, `Avatar`, `RumikAvatar`,
`Icon`, `TablePreview`, `TableArena`, `StateScreen`, `EmptyState`, `Rumik` можно и
в серверных компонентах. `RumikAvatar` и `StatusBadge` — только из файла
`@/components/ui/Avatar`, `TableArena` и детали места — из
`@/components/ui/TablePreview`: в баррель они не входят.

| Компонент | Когда | Главное в API |
|---|---|---|
| `UiRoot` | корень **каждого** экрана | `theme?`; ставит `data-ui` (без него нет базы: кегля, цвета текста, кольца фокуса) |
| `Button` | действие с текстом | `variant: primary\|secondary\|ghost\|danger`, `size: sm 32\|md 40\|lg 48`, `icon`, `iconRight`, `loading`, `block`; `buttonClass()` — для `<a>`/`Link` |
| `IconButton` | действие иконкой (док, шапка, видео) | `icon`, **`label`** (обязательно), `hint` (текст подсказки, если отличается от label), `shortcut` (в подсказке и `aria-keyshortcuts`), `showShortcut` (буква — маленькой клавишей 11 px в правом нижнем углу; на сенсорных, `pointer: coarse`, не рисуется), `disabledReason` (вместе с `disabled`: кнопка видна неактивной через `aria-disabled`, onClick не зовёт, а нажатие показывает тост с причиной — на телефоне подсказок нет), `variant: ghost\|quiet\|soft\|inverse\|danger\|signal\|danger-ghost\|scrim\|scrim-ghost` (`quiet` — тише ghost, второстепенное у главной кнопки; `scrim-ghost` — без подложки внутри scrim-плашки), `size: sm\|md\|lg\|xl\|split` (`split` 24×48 — шеврон сплит-кнопки дока, всегда круглый), `shape: square\|round`, `pressed`, `badge`, `tooltip`, `loading` |
| `Tooltip` | подсказка у не-IconButton | `content`, `side`, `delay=450`; мышь — после паузы, фокус — сразу, повторная — мгновенно |

клиентские примитивы (Dialog, Toaster, LevelMeter…), даже из серверного
компонента: на лендинге это было +20 КБ gzip (две копии барреля). В комнате это не важно (она
пользуется почти всеми), а на лёгких страницах (сайт, 404, ошибки) импортируйте
из файлов: `import { Button } from "@/components/ui/Button"`. Тяжёлое на витрине
— только лениво: рисовалка (`LazyRumikEditor`) и окно открытки (`PostcardDialog`) в
замер первого экрана не входят (§8 «Вес»).

`className` на примитиве — только для **внешних** вещей (отступы, ширина,
`self-*`, `max-sm:hidden`). Перекрашивать примитив через `className` нельзя:
`tailwind-merge` не подключён, классы не перебьют вариант. Нужен новый вид —
новый вариант в примитиве.

## 5. Паттерны

### Кто говорит, у кого мьют

В комнате человек — Румик (флаг `rumik_table`, §8), поэтому «говорит» выглядит
по-разному у фигуры, у головы и у кружка. Цвет у всех один — `signal`.

| Где | «Говорит» | Мьют |
|---|---|---|
| Румик во весь рост: стол, ряд | `glow` (лаймовая обводка по силуэту и мягкое свечение) + значок `audio-lines` в лаймовом кружке у головы (`SpeakingBadge`): его видят и те, кто плохо различает цвета. Пока правая кисть поднята (жест 👍 🔥 GG), значок стоит у правого бока, чтобы её не закрыть (`speakingBadgeSpot`). Подпись говорящего под ногами опускается на 6 px, чтобы свечение не легло на ник (только на арене от 700 px, 180 мс, при «меньше движения» сразу; числа — `SEAT_LABEL`). Уровень голоса не рисуется — место перерисовывается только при смене «говорит / молчит» | значок у руки (`SeatStatusBadge`) + перечёркнутое кольцо в глазах (`eyes="muted"`); жест реакции глаза не перебивает |
| Голова `RumikAvatar`: список, лента под сценой, мини-комната, панель участника | лаймовое кольцо вокруг плитки, без волны (обводку по силуэту на 24–44 px срезал бы край) | значок в углу, как у кружка; от 40 px ещё и глаза. В строке списка и в чипе ленты под сценой — значком после ника (18 и 16 px), а не на голове |
| Кружок `Avatar`: комната без Румиков | `<Avatar speaking level={participant.audioLevel} />`: кольцо 3 px с зазором + тонкая волна снаружи; сила идёт за громкостью, переходы 90 мс сглаживают редкие замеры LiveKit | значок в углу |

Головы в чате, тостах и чипе показа (`PersonHead`) «говорит» и уровень голоса
не показывают: голос не перерисовывает ни чат, ни тосты (§7 №5).

В тишине кольцо и обводка скрыты, ничего не считается. Мьют — значок, не
кольцо: тёмный кружок с красной иконкой (сам выключил), красная заливка (хост),
`radio` (рация ждёт — **не** выглядит как мьют). «Звук выкл» и рацию видят все:
клиент шлёт их на сервер (`POST /api/voice`), тот пишет атрибуты участника, чужое
место читает их (`useVoiceAttributes`, `remoteSeatVoice`).

### Стол под углом (комната ≥ 560 px)

Эталон — `ArenaTable` в `src/app/room/[code]/participants/ParticipantStack.tsx` и
`RoundTable` в макете `src/app/design/_mocks/room-parts.tsx`; оба стоят на
`TableArena`. Геометрия мест — `arenaLayout(n, self)` (`tableLayout.ts`, с тестом),
раскладка зоны — `zoneLayout` из `src/lib/room/zoneLayout.ts`. Мини-стол без
управления (лобби, `/clubs`) — `TablePreview` на том же `TableArena`.

- Арена 16:11, ширина `w-[min(1100px,100cqw,calc(100cqh*16/11))]`: стол
  выбирается по высоте окна и ужимается, когда открыт чат. Свет лампы над столом —
  статичный градиент.
- Стол — эллипс, Румики одного размера стоят ногами на эллипсе пошире, никто не
  залезает на стол. Места делят эллипс на равные дуги, а не на равные углы: иначе
  по бокам сбились бы в кучу.
- Размер места один на весь стол: 19 % ширины арены до 6 человек, 18 % при 7,
  14,5 % при 8–10. Тест: при 1…10 людях ни фигура, ни подпись не задевают стол и
  соседей даже на арене 500 px.
- Своё место — внизу посередине, ближе к зрителю; остальные идут от него по
  часовой в порядке входа. Ближние рисуются поверх дальних. Глаза смотрят к центру
  стола (`look`).
- Подпись — одна строка: корона, ник, «· вы», `Badge signal` «Экран» (на арене
  уже 760 px — только значок), `SignalBars poor`. Не шире места × 1,1, чтобы
  подписи соседей не сходились. У дальних мест (sin угла < −0,45) — над головой, у
  остальных — под ногами; у говорящего подпись под ногами чуть ниже (§5 «Кто
  говорит, у кого мьют»). Подписи и значки крупнеют от арены 700–760 px.
- Центр стола — прямоугольник, вписанный в эллипс (0,8·rx × 0,6·ry), контейнер
  `center`: по его высоте прячется лишнее (значок в круге и пояснения — ниже 150 и
  120 px), кнопки остаются на столе. Стол без людей (`TablePreview people={[]}`)
  крупнее в 1,45 раза, чтобы в центр влезли код и кнопка.
- Центр — место под **состояние комнаты**: код для диктовки (обычно), «Пока тут
  только вы» + «Скопировать ссылку» (без Румика: вы сами уже стоите у стола),
  «Вы показываете экран» + Превью/Стоп, «Тёма показывает экран — Смотреть» (если
  сцену скрыли).
- Клик по месту (кроме своего) открывает панель участника **сбоку от места**,
  наружу от стола (`panelFor` в `RoomMock.tsx`).
- **Запасной — круглый стол** (флаг `rumik_table` выключен): кружки `Avatar` по
  окружности, стол — круг 48 % от стороны, места на 80 % (`seatAngles` поворачивает
  рассадку на полшага: один — сверху, двое — слева и справа), подпись всегда
  снаружи (`labelAbove`), размер `w-[min(84cqmin,600px)]`. Тот же круг — в превью
  ссылок (§6.11). Центр круга бывает уже кнопки, поэтому «Пока тут только вы»
  смотрит на меньшую сторону зоны (#544):

  | Меньшая сторона зоны | Центр «Пока тут только вы» |
  |---|---|
  | от 670 | белый машущий Румик + заголовок, пояснение, `Button sm secondary` «Скопировать ссылку» |
  | 570–669 | то же без Румика |
  | 520–569 | без пояснения |
  | меньше 520 | заголовок в две строки, вместо кнопки — `IconButton soft` «Скопировать ссылку» с подсказкой |

### Раскладка по размеру зоны (компактный режим)

Зона = область под шапкой и левее чата. `zoneLayout(width, height)`:

| Зона | Раскладка |
|---|---|
| ширина < 560 | **список** как голосовой канал Discord: строки 48px, голова Румика `sm` (`RumikAvatar`; без Румиков — `Avatar sm`), состояние голоса — значком 18 px **справа** (`mic-off` / `headphones-off` красным, `radio` серым, «хост заглушил» — красный кружок; в углу аватара в списке значка нет), бейдж «Экран» — `md` |
| высота < 540 | **ряд** мест (стол не помещается): Румики во весь рост шириной 112 px, подпись под ногами; без Румиков — кружки `lg` |
| иначе | **стол** под углом (без Румиков — круглый) |

Определяем через `ResizeObserver` (срабатывает только при смене размера) и
рендерим **ровно одну** раскладку — иначе задвоятся `data-testid="participant"`.
Узкое окно (< 640 по окну): шапка 56 с иконкой «Пригласить», док — полоса во всю
ширину внизу, чат — секция **под списком** (а не поверх), диалоги — листы снизу.
В раскладке «список» чат **открыт по умолчанию** (один раз за вход, без звука и
без фокуса в поле — `useChatPanel().show()`), его можно свернуть («Свернуть
чат», `chevron-down`); со сценой зона берёт до 62 % высоты, без неё — 44 %.

### Док

Плавает по центру зоны комнаты (`lg:left-[calc((100%-var(--chat-w))/2)]`, корень
отдаёт ширину чата в `--chat-w`), на узком — полоса внизу без зазоров (`gap-0`:
восемь кнопок по 44 px влезают и в 360 px). Порядок:
`[˄ Микрофон] [˄ Звук] | [Экран] [Чат] [Реакции] [Звуки] | [Настройки] [Выйти]`. Шевроны — меню
выбора устройства (`IconButton size="split" variant="quiet"`, на узком скрыты).
Все кнопки круглые 48px; корень дока — `<section aria-label="Управление">`
(область разметки). У переключателей подпись постоянная + состояние
в `pressed` (`label="Микрофон" pressed={micOn}`), а действие — в подсказке
(`hint="Выключить микрофон"`, `shortcut="M"`). Буквы клавиш на кнопках
(`showShortcut`) — маленькая клавиша в углу; на сенсорных экранах их нет.
Неактивная кнопка с причиной («Экран» под запретом хоста или без поддержки в
браузере, «Микрофон» под мьютом хоста) — `disabled` + `disabledReason`: причина
тостом по нажатию, а не только в подсказке. Рация на сенсорном экране — «нажми и
держи» (палец на кнопке = эфир), короткое касание — подсказка «Рация: держите
кнопку, пока говорите»; мышью и с клавиатуры кнопка включает и выключает рацию.

### Реакция над местом

👍 🔥 😂 GG из кнопки «Реакции» в доке (§5 «Док»). Видят все в комнате; своя
всплывает сразу по клику, эха сервера не ждём. Код — `src/app/room/[code]/reactions/`.

- **Пузырь** (`ReactionBubble`): кружок 36 px (`h-9 min-w-9`, `bg-overlay`,
  `border-line`, `shadow-float`), значок набора 20 px (`Glyph`): 👍 — `thumbs-up` в
  `signal-ink`, 🔥 — `flame` в `caution-ink`, 😂 — `laugh` в `crown`, «GG» — `font-brand
  text-body` жирным. Корень помечен `data-reaction`,
  позицию задают классы обёртки (`[&>[data-reaction]]:…`), без inline-стилей.

  | Где | Пузырь |
  |---|---|
  | стол под углом, ряд | над головой (`SEAT_HEAD_STYLE`); у круглого стола — над кружком |
  | дальние места стола под углом (ник над головой) | слева от ника, на его строке: сбоку от головы в жестах 🔥 и GG подняты руки |
  | дальние места круглого стола | слева от кружка |
  | строка списка, мини-комната | поверх головы: сверху его срезала бы прокрутка, сбоку он лёг бы на ник |

- **Время:** живёт 2 с. Появление 200 мс (`@starting-style`: opacity, scale,
  translate), уход 140 мс; при «меньше движения» — без сдвига и масштаба. Таймеры
  заводятся на событие, в покое ничего не тикает.
- **Жест Румика** — только у фигуры за столом и в ряду, на те же 2 с; поза
  меняется сразу, без анимации. Мьют в глазах жест не перебивает. При «меньше
  движения» жеста нет: Румик не меняет ни позу, ни глаза, остаётся только пузырь
  (`useReactionGesture`).

  | Реакция | Жест |
  |---|---|
  | 👍 «Класс» | машет: `pose="wave"` |
  | 🔥 «Огонь» | руки вверх: `cheer` |
  | 😂 «Смешно» | держится за живот и подмигивает: `laugh` + `eyes="wink"` |
  | GG «Хорошая игра» | руки вверх, глаза круглые: `cheer` + `wide` |

- **Скринридер:** пузыри `aria-hidden`; чужие реакции объявляет одна вежливая
  live-область на комнату (`ReactionFeed`, `reactions-live`): «Боря: огонь».
  Каждое объявление — новая строка (повтор тоже слышно), хранятся последние 3.
  Одного человека — не чаще раза в 2 с, что пришло в паузе, склеивается: «Боря:
  огонь 3 раза, смешно».
- **Перерисовки:** подписка по участнику — реакция Бори будит только место Бори
  (§7 №5).
- **Лимит:** клиент шлёт не больше 5 за 5 с, дальше тост «Слишком часто. Подождите
  N с» (`id: reaction-limit`); сервер режет 10 за 5 с — для тех, кто шлёт в обход
  клиента. Сервер отказал — своя реакция убирается, причина — тостом.
- **Сервер:** `POST /api/reaction` (кто — по подписи токена; флаг `reactions` по
  комнате) рассылает data-пакет от своего имени всем в комнате (тема
  `REACTION_TOPIC`). Пакет от участника — подделка, его отбрасывает
  `readReactionData` (`reactions/feed.ts`). Истории нет.

### Соундборд

Кнопка «Звуки» в доке (§5 «Док»), флаг `soundboard` (по умолчанию выключен): звуки
«для всех», как у Discord, но без Nitro. Код — `src/app/room/[code]/sounds/`,
воспроизведение — `src/lib/audio/soundboard.ts`. Эмодзи нет: звук — подписанная
кнопка («Ба-дум-тсс»), картинка не объяснила бы, что за звук.

- **Откуда звуки.** Три источника в одной панели (`catalog.ts`):
  1. **Готовый набор** — файлы `public/sounds/` и `pack.json`; собирается командой
     `npm run sounds:pack` из папки `sounds-src/` (README там же). Есть хотя бы один —
     показываются они;
  2. **вшитые** — восемь синтезированных на Web Audio: запасной набор, пока готового нет;
  3. **свои звуки комнаты** — любой участник добавляет файл (флаг `soundboard_upload`, по
     умолчанию выключен): mp3, ogg, wav или m4a, до 300 КБ и 8 секунд. Файл лежит на сервере
     (Redis, как состояние комнаты, 48 ч), у всех появляется на панели. До 12 на комнату, три
     загрузки за 10 минут на человека. Убрать звук может добавивший и хост.
- **По сети** идёт только имя звука (`POST /api/sound` → data-пакет `SOUND_TOPIC`),
  файл каждый берёт сам (`/sounds/…` или `GET /api/sounds/<id>?code=…`, кеш `private,
  immutable`). Имя неизвестного клиенту звука молча не играет. Файл проверяется по
  первым байтам (mp3, ogg, wav, m4a, webm), а не по расширению; длину считает клиент
  (`decodeAudioData`), сервер держит потолок по байтам.
- **Над местом** всплывает один значок `music` (§5 «Реакция над местом»); какой звук —
  слышно и написано в ленте скринридера: «Боря: Ба-дум-тсс».
- **Громкость и тишина:** звуки других — отдельная громкость (50 %) и выключатель «Слышать
  звуки других» (в панели и в настройках); свои слышно всегда, «Звук выкл» глушит всё. Не
  длиннее 8 с, сразу звучат не больше трёх; новый звук того же человека обрывает прежний.
- **Лимит:** клиент шлёт не больше 3 за 10 с (тост «Слишком часто», `id: sound-limit`);
  сервер режет 6 за 10 с на человека и 10 за 10 с на комнату.
- **Звук входа:** свой звук из готового набора или вшитых (настройки → «Звуки»); его слышат
  все вместо обычного «вошёл», над вошедшим всплывает значок. Лежит в атрибуте участника
  `sound.enter`, который сервер кладёт в токен.

### Свой статус

Под флагом `statuses` (по умолчанию выключен): пункт «Мой статус» в меню комнаты открывает

### Тосты

Мимолётные события: вошёл, вышел, права, замок, начался показ, ошибка действия.
В комнате — `<Toaster placement="top-left" />`, место задаёт переменная
`--gr-toast-top` на корне (считает `useToastTop` в `feed/`): на широком — сверху
слева под шапкой, но **ниже плашек** над зоной; при сцене — под её плашкой «Эфир»;
в узком окне (список) — сразу под последней строкой списка (на стыке с чатом, без
чата — в пустоте под списком), длинный список — над доком. Не больше 3 видно,
4 с (ошибка 7 с). Пауза — пока мышь **двигается** над тостами и пока вкладка
скрыта; тост, выехавший под неподвижный курсор, не замирает, а после клика по
кнопке в тосте пауза снимается до следующего движения. Тот же `id` обновляет
тост на месте и заново заводит таймер. Ответ на нажатие (`immediate`) в очереди
не ждёт.

Человек слева во «вошёл», «вышел» и сообщении в чат — голова Румика 32 px
(`toastPerson` из `feed/PersonHead.tsx`), без Румиков — кружок. Голова живая:
рисунок, пришедший через 0,5–1,5 с после входа человека, встаёт в уже показанный
тост. Автор сообщения уже вышел — голова только его цвета.

Тексты — ник в заголовке, событие в описании, без склонений:
`{title: "Ника", description: "теперь в комнате", person}` ·
`{title: "Лёха", description: "больше не в комнате", person}` ·
`{title: "Тёма", description: "выгнали на 5 минут", icon: "user-x", id: "peer-…"}` (тот же id, что у «вышел»: один тост на кик) ·
`{title: "Вы теперь хост", description: "Настройки комнаты — в меню названия", icon: "crown"}` ·
`{title: "Ника теперь хост", icon: "crown"}` ·
`{title: "Вход закрыт", description: "Новые люди не смогут зайти", icon: "lock", tone: "caution"}` /
`{title: "Вход открыт", description: "Новые люди снова могут зайти", icon: "unlock"}` ·
гостям — «Показывать экран теперь может только хост / могут все / можно по
разрешению хоста» (id `room-host`, `room-lock`, `room-screen-policy`) ·
`{title: "Тёма показывает экран", icon: "screen-share", tone: "signal", action: {label: "Смотреть"}}` —
только если показ не вышел на сцену сам; гаснет, когда вышел или закончился.
Тост сообщения в чат (`chat-incoming`) гаснет, как только чат открыли любым способом.

Тост — не для того, что держится (нет микрофона, хост заглушил): это
`InlineAlert` над столом, пока причина не уйдёт. Всё, что значит «вас не
слышно» (нет доступа, микрофон занят или не найден, хост заглушил), — `alert`,
как красная кнопка микрофона; «Хост выключил чат» — `info`, и пока панель чата
открыта, плашки нет (та же причина написана под полем ввода).

## 7. Железные правила для исполнителей

1. Корень экрана — `UiRoot`. Внутри — только примитивы и токен-классы. Никаких
   своих глобальных классов в `globals.css`, hex (кроме краски рисунка, §8),
   `dark:`.
2. Одна главная кнопка (`primary`) на экран. Красная заливка — только «не слышно»
   и необратимое. `signal` — только «передаёт».
3. У каждой кнопки-иконки — `label`; у горячих клавиш — `shortcut` из
   `formatKeyCode(binds.x)`. У группы (`SegmentedControl`, `Menu`) — `label`.
4. Ничего не анимировать в покое; анимации — `transform`/`opacity`, ≤ 240 мс,
   только CSS; поверх видео — без blur и теней.
5. Перерисовки: уровень голоса меняет только свой аватар, а «говорит», рисунок и
   реакция — только своё место (мемо-места, `useIsSpeaking`/`useIsMuted`,
   `useAvatarPaint`, `useReactionGesture` на участника), а не всю комнату.
6. Раскладка зоны — ровно одна в DOM; testid из брифа — сохранить.
7. Узкое окно 390 и 1024 — обязательная проверка каждого экрана.
8. Тексты: ник не склоняем, без тире-украшений, технические ошибки — не на экран.
9. Новая иконка — в `icons.tsx` (геометрия Lucide), не инлайном в экране.
10. Не нашли нужное в примитивах — добавьте вариант в примитив и в витрину, а не
    стилизуйте «по месту».
11. Румик и украшения — только по §8: витрина украшается, рабочие экраны нет.
    В рабочем экране Румик — это человек (место за столом, голова в списке, «Ваш
    Румик» в лобби) или картинка пустого и ошибочного состояния. Двигается он там
    только жестом на реакцию: по событию, ≤ 2 с. Новая часть Румика в комнате или
    лобби — со своим флагом-выключателем.

## 8. Бренд-слой

Маскот Румик, рисунки людей на нём и оформление витрины — сознательное
исключение из принципов 1 и 3 (§2), и только там, где разрешено ниже. Живой
каталог — `/design/rumik`, рисовалка — `/design/editor`.

### Два слоя

| Слой | Где | Правило |
|---|---|---|
| Рабочий | комната, лобби, настройки, диалоги, админка | как во всём документе: цвет только от людей и событий, декора нет. Румик здесь — **человек или состояние**, а не украшение: место за столом и голова в списках (R3), «Ваш Румик» в лобби — свой аватар (R2), картинка пустого или ошибочного состояния вместо значка |
| Витрина | главная, `/pricing`, `/clubs`, `/rooms`, 404 и страницы ошибок | Румик, декор по краям, «стена», рисовалка в герое |

Проверка для рабочего экрана: Румик там либо **кто-то** (человек в комнате, вы
сами), либо **что-то случилось** (пусто, ошибка). Румик «для красоты» — только на
витрине.

### Кто такой Румик

Глаза взяты из логотипа: в слове «room» две «о» — пустое кольцо и лаймовый круг.
Кольцо «слушает», круг «говорит» — та же пара, что кольцо «говорит» в комнате и
знак логотипа. Глаза разные — это главная узнаваемая деталь. Стиль — плоская
наклейка.

| Часть | Как |
|---|---|
| Тело | скруглённый квадрат, цвет — палитра аватаров: один или четыре по четвертям |
| Лицо | тёмная плашка `--gr-avatar-ink`: глаза читаются на любом цвете тела и в любой теме |
| Руки и ноги | короткие и толстые, монолиния с круглыми концами — как штрихи логотипа; обводка `--gr-avatar-ink` |
| Наклейка | `sticker`: белый край `--gr-rumik-sticker` по силуэту |

Геометрия одна на SVG, рисовалку (маски частей) и стол (`tableLayout.ts`) —
`src/lib/rumik/geometry.ts`.

### Глаза = сигналы продукта

| `eyes` | Что значит | Где |
|---|---|---|
| `normal` | кольцо слушает, лаймовый круг говорит | по умолчанию |
| `wink` | всё хорошо, заходи | «Вы вышли», приглашения, жест на 😂 |
| `sleep` | спит, нет активности | «Открытых комнат нет», подвал сайта |
| `wide` | удивлён: что-то не по плану | «Комната заполнена», «Что-то пошло не так», жест на GG |
| `muted` | микрофон выключен: кольцо перечёркнуто `alert`, как значок мьюта | место за столом и голова от 40 px при мьюте (R3) |
| `lost` | связь потеряна: крестик вместо кольца | только «Связь потеряна» |
| `speak` | говорит: лаймовый круг крупнее | картинки на витрине. Это **не** индикатор «говорит» в комнате: там `glow` и значок у головы (§5 «Кто говорит, у кого мьют») |

Глаза со смыслом (`muted`, `lost`) — только там, где это правда. Для настроения —
`normal`, `wink`, `sleep`, `wide`, `speak`. Жест на реакцию глаза мьюта не
перебивает: перечёркнутое кольцо — правда о микрофоне.

### API

`import { Rumik } from "@/components/ui/Rumik"` — на лёгких страницах из файла, а
не из барреля (§4 «Вес страницы»). В серверном компоненте JS в браузер не
добавляет; внутри клиентского (страницы ошибок, `OpenRooms`, `RecentRooms`,
`SessionScreen`, места в комнате) его код (~3 КБ после сжатия) едет в бандл этого
компонента. Голова для списков — `RumikAvatar`, стол — `TableArena` (§4).

| Проп | Значения |
|---|---|
| `colors` | индекс палитры 0–9 · до 4 индексов по четвертям (верх-слева, верх-справа, низ-справа, низ-слева) · `"white"`; по умолчанию 6 |
| `pose` | `stand` · `wave` · `waveL` · `cheer` · `point` · `sit` · `hold` · `laugh` (держится за живот: жест 😂) |
| `eyes` | таблица выше |
| `hat` | `cap` · `beanie` · `crown` (хост, Pro, владелец клуба; цвет `crown`) · `shades` |
| `extra` | `q` «?» · `bang` «!» · `zzz`; буквы не отражаются вместе с `flip`. Дуг и волн у лица нет (решение по индикатору «говорит») |
| `sticker` · `glow` | белый край наклейки · «говорит»: лаймовая обводка по силуэту и мягкое свечение |
| `look` · `tilt` · `flip` | взгляд, сдвиг до ±4 · наклон до ±15° · смотрит в другую сторону (отражение вокруг середины рамки, как `scaleX(-1)`). `look` и `tilt` — в координатах экрана и при `flip`: `look={[-3, 0]}` — влево |
| `size` | ширина в px; без него — во всю ширину контейнера (рамка 286×240, `RUMIK_ASPECT`) |
| `label` | подпись для скринридера; без неё `aria-hidden` (в пустом состоянии смысл несёт заголовок) |
| `paint` | рисунок человека: адрес PNG слоя краски (data URL из браузера или `/api/avatar/<id>`) в рамке 286×240 или кратно, нарисованный на стоящем Румике. Ложится по частям тела и в других позах едет с руками и ногами (`partTransform`). Половина руки, спрятанная в позе «стоит» за телом, закрашивается отражением видимой (`armMirror`): у поднятой руки нет клина цвета туловища. Лицо, глаза, шапка и обводка — поверх, поэтому `glow` и `eyes="muted"` видны и на рисунке. Под рисунком — `colors="white"` |
| `frame` | `full` (по умолчанию) · `head` — квадратная рамка по голове с шапкой: миниатюры «Мои Румики». Руки и ноги выходят за неё (`overflow: visible`); нужна только голова — `overflow-hidden` у обёртки |

От 48 px читаются глаза и шапка; на 24–32 px — только силуэт и цвет, значки и
глаза со смыслом там не ставим.

```tsx
// 404: вместо значка в круге
<StateScreen visual={<Rumik colors={[6, 7, 8, 5]} sticker extra="q" look={[3, -2]} tilt={-6} />} title="Такой страницы нет" … />
// Пустой список
<EmptyState visual={<Rumik colors={[4, 3, 5, 6]} sticker eyes="sleep" extra="zzz" size={180} />} … />
// Декор: сидит на линии секции справа и смотрит на страницу
<SideDecor side="right" sit><Rumik pose="sit" colors={[8, 9, 0, 1]} sticker hat="beanie" eyes="wink" flip /></SideDecor>
// Место за столом: свой рисунок или цвет человека
<Rumik colors={paint ? "white" : colorIndex} paint={paint ?? undefined} glow={speaking} eyes={muted ? "muted" : "normal"} look={seat.look} />
```

### Цвета

- Только токены: тело `--gr-avatar-0…9`, лицо и обводка `--gr-avatar-ink`, глаза
  `--gr-rumik-eye` и `--gr-signal`, черта мьюта `--gr-alert`, корона `--gr-crown`,
  наклейка `--gr-rumik-sticker`, белый Румик `--gr-rumik-white`. Ни одного hex:
  светлая тема перекрашивает тело сама, лицо остаётся тёмным (`--gr-rumik-*` в
  светлой теме не меняются).
- В SVG цвет — через `style={{ fill: "var(--gr-…)" }}`, а не атрибутом `fill`.
- В комнате цвет Румика значит человека: участник — цвета своего аватара
  (`assignAvatarColors`, как был кружок) или белый под своим рисунком. Румик
  пустого состояния (у круглого стола) — белый: он не участник.
- **Исключение из «без hex» — краска рисунка.** Палитра рисовалки
  (`src/lib/rumik/palette.ts`, 15 цветов) — hex: краска запекается в PNG и должна
  выглядеть одинаково в любой теме и у любого зрителя. Это данные человека, а не
  цвет интерфейса. Всё остальное в рисовалке — токены: фигура на холсте (белый
  Румик, обводка) читает их через `getComputedStyle`, радуга «любой цвет» — из
  `--gr-avatar-*`. Образцы рисунков на витринах красят той же палитрой
  (`_mocks/rumikSamples.tsx`).

### Румик за столом (R3)

Разрешённое исключение рабочего экрана: это не украшение, а сам человек вместо
кружка с инициалами. Цвет — цвет человека, рисунок — его собственный. Как стоят
места, подписи и центр стола — §5 «Стол под углом»; «говорит» и мьют — §5 «Кто
говорит, у кого мьют».

- **Индикатор «говорит» сделан так, как утверждён:** тонкая лаймовая обводка по
  силуэту и мягкое свечение за фигурой (`glow`), значок с полосками у головы
  (`SpeakingBadge`) — его видят и те, кто плохо различает цвета. Дуг у лица нет,
  свечение не закрывает подпись. У головы `RumikAvatar` — кольцо вокруг плитки.
- В покое фигура стоит; движение — только жест на реакцию (ниже).
- Перерисовки: «говорит», рисунок и жест слушает само место (`SeatFigure`,
  `LiveHead`), соседей это не трогает (§7 №5).
- Выключатель — `rumik_table`: без него прежний круглый стол с кружками.

### Рисовалка (R2)

Человек раскрашивает своего Румика, и таким его видят в комнате. Где: герой
главной (`variant="hero"`, область `<section>` со скрытым h2 «Ваш Румик») и окно
«Ваш Румик» в лобби (`variant="dialog"`, «Готово» в шапке окна); витрина —
`/design/editor`. На страницу ставится только `LazyRumikEditor`
(`variant`, `actions`, `onEvent`, `className`), в `actions` кладут
`PostcardButton`. По отзыву автора в рисовалке нет «Спереди / Сзади», кружков «так
вас увидят» и подсказки над инструментами.

Раскладку выбирает ширина **контейнера** (container queries), а не окна:

| Ширина контейнера | hero | dialog | Раскладка |
|---|---|---|---|
| широко | ≥ 600 | ≥ 560 | три колонки: панель инструментов столбиком, фигура, «Цвет» |
| средне | 480–599 | 460–559 | панель строкой сверху, под ней фигура и «Цвет» рядом |
| узко | < 480 | < 460 | всё столбиком; уже 448 / 400 px панель — в два ряда |

Кнопки панели: в hero — 40 px, в dialog — 32 px. Блок фигуры обрезан по ширине
(`overflow-x-clip`): рамка SVG шире сцены и на узком экране давала бы
горизонтальную прокрутку.

| Что | Как |
|---|---|
| Инструменты | `role="toolbar"`, стрелки между кнопками: кисть `B`, ластик `E`, заливка части `G`, пипетка `I` · зеркало `M` · назад `Ctrl+Z`, вперёд `Ctrl+Shift+Z` / `Ctrl+Y`, «Стереть всё» · «Сохранить файл» (`save`, дискета) и «Загрузить свой» (`upload`) |
| Клавиши | по `e.code` — в любой раскладке; не работают в полях ввода и когда поверх рисовалки чужое окно, в том числе вложенное (открытка в окне лобби) — `editorOwnsKey`; вне экрана тоже не работают |
| Неактивные кнопки | «Назад», «Вперёд», «Стереть всё», «Сохранить файл» без истории или рисунка — `aria-disabled`: остаются в фокусе и в обходе стрелками, причина — в подсказке, тоста нет |
| «Цвет» | 15 кружков палитры, «любой цвет» (системный выбор; кольцо фокуса — на круге), поле HEX, «Размер» кисти 4–64 |
| Заливка и пипетка | заливка части учитывает полупрозрачные края штрихов: светлых «волосков» вдоль них не остаётся; пипетка прилипает к цвету палитры на ±2 по каналу |
| «Мои Румики» | под фигурой, прошлые рисунки, до 8: миниатюры 36 px с переносом строки (`Rumik frame="head"`), клик — вернуть, крестик 24 px (зона нажатия 28) — убрать, после него 6 с висит «Удалено · Вернуть». Место держится заранее: в широкой раскладке — под ряд, в средней — под два ряда, в узкой не держится. Тот же рисунок второй раз не ложится (сравнение по пикселям) |
| Хранение | в браузере (`src/lib/rumik/storage.ts`): `gr.rumik.v1` — текущий рисунок, `gr.rumik.v1.gallery` — «Мои Румики». На все рисунки — бюджет 1,5 млн символов (`RUMIK_BUDGET`): галерея урезается от старых заранее, а не когда браузер уже отказал; ранний формат переезжает сам; нет хранилища — живёт в памяти вкладки. Дорисовка — `updateMyPaint` (заменяет текущий), смена рисунка (загрузка файла, «Стереть всё», возврат из «Моих Румиков») — `saveMyPaint` (прежний уходит в «Мои Румики»). Читать — `useMyPaint()` (снимок — сама строка: место за столом не перерисовывается от галереи), `useRumikStore()`; работает и между вкладками |
| Файл | PNG слоя краски 572×480 (рамка 286×240 × 2), прозрачный вне фигуры и там, где краски нет. «Сохранить файл» — всегда `rumik.png` 572×480; «Загрузить свой» принимает 572×480 или 286×240 (растянется), до 4 МБ. Не тот файл — одна фраза: «Это не рисунок Румика. Подойдёт файл из «Сохранить файл».» (`UPLOAD_ERROR`) |
| Глаза | следят за курсором только по `pointermove` (кадр на пачку событий); при «меньше движения» и вне экрана стоят |
| Загрузка | код рисовалки — отдельный кусок, грузится, когда рисовалка в 300 px от экрана. До него — неподвижная заглушка той же раскладки (`EditorGrid` в `editorLayout.tsx`) со своим рисунком: нулевой CLS |
| Холст | скругления через `arcTo`: `roundRect` есть не во всех Firefox и Safari |
| Аналитика | `rumik_editor_opened` (окно в лобби), `rumik_paint_started` (раз за визит на каждом месте), `rumik_file_saved`, `rumik_file_loaded`, `rumik_postcard_downloaded`, `rumik_postcard_shared` (с позой); у всех `place: hero\|lobby`. Каждое уходит в PostHog и маяком `POST /api/ev` в поток событий сайта (`t: "rumik"`) — без ника, комнаты и IP, с номером браузера `gr:vid`; на `/design` не считаются. Имена — строгий белый список `RUMIK_EVENTS`, места — `RUMIK_PLACES` (`platform.ts`): новое событие сначала добавить туда, иначе маяк молча отбросят. В админке — «Аналитика» → «Румик» |

Цвета краски — выше, «Цвета» (исключение из «без hex»).

### Рисунок виден всем (R4)

| Что | Как |
|---|---|
| Свой | в комнате — сразу из браузера (572×480), без ожидания сервера |
| Другим | `AvatarSync` уменьшает рисунок до 286×240 и шлёт `POST /api/avatar`: при входе — сразу, рисунок, сменённый уже в комнате (рисуют в соседней вкладке), — после 15 с без правок, и не чаще раза в 5 с. Только когда в комнате включены и `rumik_share`, и `rumik_table`: без стола рисунок никто не увидит. Сбой сети — тихо: комната работает и без рисунка |
| Размер | до 32 КБ (`AVATAR_MAX_BYTES`). Не влез — клиент огрубляет цвета: 16, потом 8, потом 4 ступени на канал. Не влез и так — другие видят Румика его цвета без рисунка |
| Отказ | сервер не принял рисунок — один запрос `png: null`, и своё место показывает то же, что видят другие (а не рисунок из браузера). Скрыт администрацией (`AVATAR_BLOCKED`) — один тост `caution` («Этот рисунок скрыла администрация. Нарисуйте другой» или «Администрация скрыла ваши рисунки в этой комнате»); остальные отказы — молча |
| Сервер | проверяет PNG: ровно 286×240, до 32 КБ, без анимации; лишние чанки (текст, EXIF) выкидывает. Кладёт по хэшу содержимого и пишет участнику атрибут `avatar.id`. Чей рисунок, сервер обычно не знает: связь «кто нарисовал» записывается только в жалобе и в журнале админки |
| Чужой | `GET /api/avatar/<id>`: адрес не меняется, пока не поменялась картинка; кеш — `private, max-age=31536000, immutable` |
| Срок | 30 дней от последнего использования (каждый вход с тем же рисунком продлевает), потом стирается сам |
| Кто видит | люди в той же комнате: картинка открывается по ссылке, которую знают участники комнаты (переслать её дальше они могут сами). Публичной галереи нет. Текст для людей — `/privacy`, «Рисунок Румика», и вопрос в FAQ |
| Модерация | в админке «Сбросить рисунок» (значок `Eraser`) — в ряду действий над участником и в жалобе; с причиной и записью в журнал. Рисунок пропадает у всех, в комнате человек — обычный Румик своего цвета; этот рисунок не загрузится снова 30 дней, а новые рисунки этого человека в этой комнате не примутся 48 ч (пока жива комната). Скрытую картинку админка видит ещё 180 дней, как жалобу (`gr:avatarhidden:<id>`). Миниатюры: 48 px у участника, 38 px в жалобе, в строке журнала |
| Нет рисунка | Румик цвета участника; рисунок не загрузился — белый |
| Лимиты | 4 отправки за 15 с на участника. Новые рисунки (повтор лежащего не считается): 20 за 10 мин с адреса (IPv6 — по сети /64), на комнату за 10 мин и суточный бюджет всего сайта (`AVATAR_LIMIT`, 429). Два последних — в админке, «Продукт» → лимиты «Рисунки Румика»: `avatarNewPerRoom` (по умолчанию 40, 1–500) и `avatarDayBudgetMb` (8 МБ, 1–32), пределы — `AVATAR_LIMIT_BOUNDS`. Чтение — 300 в минуту с адреса. Сколько места заняли рисунки — «Здоровье» → «Рисунки Румика» |

Макеты `/design` `useAvatarPaint` не зовут (комнаты там нет): свой рисунок —
`useMyPaint()`.

### Реакции и жесты (R5)

Жест — **единственное** разрешённое движение Румика в комнате: только по событию
(реакция 👍 🔥 😂 GG, звук соундборда или игра, §5 «Соундборд», «Игры»), не дольше 2 с, поза меняется без анимации; в покое Румик
стоит, при «меньше движения» жеста нет вовсе. Жесты собраны из поз и глаз Румика;
для 😂 добавлена поза `laugh` (держится за живот). Таблица жестов, пузырь и
лимиты — §5 «Реакция над местом»; витрина — `/design/rumik`, блок «Жесты реакций».

### Декор по краям

Колонка витрины — 1200 px, по бокам пустые полосы. В них — украшения из
`src/components/marketing/decor/`, по месту: в проп `decor` у `Section` из
`components/marketing` (секция во всю ширину и `relative`).

| Компонент | Что | Как |
|---|---|---|
| `SideDecor` | Румик в боковой полосе | `side`, `top` (px от верха секции) или `sit` (сидит на линии сверху секции), `column` (ширина колонки, по умолчанию 1200); ширина сама, clamp(100px, (100vw − 1200px)/4, 210px); справа — `flip`, чтобы смотрел на страницу |
| `DecorSquare` | тихий скруглённый квадрат-«конфетти» | `inset` — отступ от колонки наружу, `size`, `color` (индекс палитры), `rotate`, `column`; контурный полупрозрачный или `filled` |

- Только от 1400 px окна; уже — не рисуется. (В макете было 1380: на Windows полоса
  прокрутки отнимает 17 px, и на 1380–1395 Румик заезжал на колонку.)
- Целиком: край окна ничего не обрезает.
- `aria-hidden`, `pointer-events-none`, `absolute` от секции: нулевой CLS, без
  горизонтальной прокрутки.
- В каждой боковой полосе — не больше одного-двух ярких Румиков на экран; квадраты
  и фон тихие. Румики внутри колонки (над карточками тарифов, в финальном призыве)
  — по одному на карточку и с той ширины, где им хватает места (`lg`, `xl`).
- Румик внутри секции (не в полосе) — с классом `DECOR_OFF`, чтобы его прятал
  выключатель.

### «Стена»

`DecorWall` (без пропсов) — по одному разу на страницу витрины (главная,
`/pricing`, `/clubs`, `/rooms`), не в общем layout: на юридических страницах стены
нет.

- От 1700 px; `position: fixed` — прибита к окну и не обрывается на короткой
  странице. Позади содержимого (`-z-10`, корень витрины — `UiRoot` с `isolate`).
- Три слоя квадратов: чем дальше слой, тем он мельче, размытее и медленнее.
  Скорости ≈ 0,08 / 0,2 / 0,42 от прокрутки.
- Края гаснут маской: к колонке, к краю экрана, сверху и снизу. Резкого обреза нет.
- Движение — только `transform` по событию прокрутки, не больше одного кадра на
  пачку событий; постоянного цикла нет. При «меньше движения» и уже 1700 px
  прокрутку не слушает.
- Цвета — палитра аватаров с низкой непрозрачностью.

### Выключатели

Все включены по умолчанию: решение автора «всем сразу, у каждой части свой
выключатель», деления посетителей на группы нет. Флаги — в админке
(`FEATURE_FLAGS` в `src/lib/api/platform.ts`).

| Флаг | Действует | Что прячет | Что вместо |
|---|---|---|---|
| `rumik_decor` | весь сайт | края, «стену», Румиков в секциях витрины (всё с `DECOR_OFF`) | пусто; пустые состояния и 404 с Румиком остаются |
| `rumik_editor` | весь сайт | рисовалку в герое; «Ваш Румик» и окно «Раскрасить» в лобби, а с ними открытку | на главной — круглый мини-стол с кружками (`TablePreview variant="avatars"`); в лобби — ничего. Уже нарисованное в комнате остаётся (его прячет `rumik_share`) |
| `rumik_table` | по комнате; «Недавние» и `/rooms` читают общее значение (без кода комнаты) | Румиков за столом и в ряду; головы в списке, ленте, мини-комнате, панели участника, чате, тостах и чипе показа; в лобби — стопку и мини-стол из Румиков и «Ваш Румик»; отправку своего рисунка (без стола его никто не увидит); головы в «Недавних» и на `/rooms` | прежние кружки `Avatar` и круглый стол. Мини-стол на `/clubs` не трогает |
| `rumik_share` | по комнате; выключен совсем — `/api/avatar/<id>` не отдаёт картинки никому | рисунки в комнате — у всех, и у себя; сервер новые не принимает (`FEATURE_DISABLED`) | Румики цвета участников |
| `reactions` | по комнате | кнопку «Реакции» в доке; сервер отвечает `FEATURE_DISABLED` | — |

«Весь сайт» — признак `roomless: true` у флага в `FEATURE_FLAGS` (`isRoomlessFlag`;
`ROOMLESS_FLAGS` сайт вычисляет из него): только вкл/выкл, доли и списка комнат
нет — сайт такие правила отвергает, админка показывает только тумблер с подписью
«на весь сайт». «По комнате» можно включить части комнат или списку комнат. В браузере флаги читает `usePublicConfig(code?)`,
в комнате — `useRoomConfig()`, на сервере — `isFlagOn(await
loadRuntimeConfig(), "<флаг>", code)`. До ответа `/api/config` всё ведёт себя как
включённое.

**`rumik_decor`** («Украшения сайта: Румики по краям и «стена»»). Выключен —
`DecorSwitch` (смонтирован в `src/app/(site)/layout.tsx`) ставит
`data-decor="off"` на `<html>`, и всё с классом
`DECOR_OFF` прячется: края, «стена» (снимается целиком, вместе со слушателем
прокрутки), Румики в секциях, над карточками тарифов, в финальном призыве и в шаге
«Слышите друг друга». Пустые состояния и 404 с Румиком остаются: это картинка
состояния, а не украшение.

Срабатывает в браузере, после ответа `/api/config`: сервер отдаёт страницу с
декором, поэтому при выключенном флаге он на миг виден, а без JS остаётся.
Отступы под Румиков (над карточками тарифов, над финальным призывом) остаются —
иначе страница прыгала бы при загрузке.

### Чего нельзя

- Румик-украшение в рабочих экранах (комната, лобби, настройки, диалоги, док,
  меню, админка). Можно только Румика-человека (место, голова, «Ваш Румик»),
  картинку пустого или ошибочного состояния и рисовалку в окне «Ваш Румик».
- Анимация в покое. Румик статичен: «стена» движется только от прокрутки, глаза в
  рисовалке — только за курсором, жест в комнате — только на реакцию и ≤ 2 с.
- hex и цвета мимо токенов; `dark:`/`light:`. Исключение — краска рисунка
  (палитра рисовалки).
- «Говорит» через `eyes="speak"` или дуги у лица: в комнате только `glow` + значок.
- Глаза со смыслом (`muted`, `lost`) «для красоты».
- Картинки нейросети в продукте — только свой SVG (`Rumik`): растр не
  перекрашивается под тему и весит в десятки раз больше. Рисунок человека — слой
  краски поверх этого SVG, а не отдельная картинка.
- Публичная галерея рисунков и ссылки на них за пределами комнаты. На сервер
  рисунок уходит только из комнаты и только на 30 дней.
- Новая часть Румика в комнате или лобби без своего выключателя.
- 3D и новые библиотеки.
