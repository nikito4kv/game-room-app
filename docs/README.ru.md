# Game Room (подробное описание на русском)

Короткое описание на английском — в [README.md](../README.md).

Лёгкая голосовая комната для компании друзей. Без регистрации: создал комнату, отправил
ссылку, друзья зашли.

- **Голос** — свой шумодав (RNNoise с умным порогом и калибровкой), автогромкость,
  режим рации, выбор микрофона и наушников, громкость каждого участника для себя.
- **Чат** — с историей для тех, кто зашёл позже, и кликабельными ссылками.
- **Показ экрана** — профили «Лёгкий» 720p60, «Игры» 1080p60, «Максимум»
  1440p60 и «Текст» для кода и документов; звук показа, полный экран, зум.
- **Права хоста** — кик, бан, заглушить, замок, пароль, кто может показывать экран и
  писать в чат, передача прав. Создатель комнаты всегда может вернуть себе права.
- **Мини-комната поверх игры** — кто говорит и кнопка микрофона (Chrome и Edge).

Сайт: https://game-room.space. Работает на своём LiveKit; как
развернуть — в [deploy/README.md](../deploy/README.md). Почему сделано именно так — в
[DECISIONS.md](DECISIONS.md).

## Запуск локально

```bash
npm install
npm run stack:fetch                            # один раз: LiveKit и Redis в .dev-stack/
cp scripts/dev-stack/env.example .env.local
npm run stack                                  # LiveKit :7880, Redis + REST как у Upstash :8079
npm run dev                                    # http://localhost:3000
npm run smoke                                  # два браузера заходят в комнату и слышат друг друга
```

Стенд (`scripts/dev-stack/`) повторяет прод: тот же LiveKit, Redis по протоколу
Upstash, вебхуки LiveKit приходят на сайт. Открывать сайт — по `localhost`, а не
`127.0.0.1`: дев-сервер Next отдаёт свои скрипты только своему адресу. Переменные
для прода — в `.env.example`.

### Сквозные (e2e)

Живые «люди» в системном Chrome (фейковые микрофон с речью из `.dev-stack/speech.wav` и
захват экрана) заходят в комнату через лобби, как настоящие. Нужны стенд, сайт и Chrome.
Файла речи в git нет: если его нет, первый прогон на Windows сам синтезирует его системным
голосом (русским, если он установлен, иначе английским). На другой системе положите туда
любой wav с речью (48 кГц). Без речи Chrome вместо голоса пищит, и рация (`ptt`) падает
с подсказкой «на входе не речь».

```bash
npm run e2e                                          # все сценарии, сайт на http://localhost:3000
node e2e/run.mjs http://localhost:3100 --only=voice,chat   # выбранные; --skip=restart — без них
node e2e/run.mjs --list                              # список сценариев
```

Сценарии (`e2e/scenarios/`, каждый сам создаёт себе комнату): `join` — лобби, пароль, нет
комнаты, вторая вкладка; `voice` — четверо слышат всех в оба уха, кольцо, M, D; `ptt` —
рация; `chat`; `screen` — показ, 1080p у зрителя, «i», F, зум, остановка; `host` — мьют,
«всем», права, кик, бан, замок; `resilience` — сеть пропала, LiveKit потерял комнату;
`restart` — перезапуск стенда; `voice-state` — «звук выкл» и рацию видят другие; `csp` —
заголовки и нарушения CSP (на прод-сборке, `next start`), загрузка шумодава; `avatar` —
рисунок Румика виден другим (`/api/avatar`, отказ и скрытие); `reactions` — 👍 🔥 😂 GG
у других, очередь, флуд и клавиатура в поповере.

- `restart` гасит и поднимает весь стенд. Он работает, только если стенд запущен отдельным
  процессом и его PID лежит в `.dev-stack/stack.pid`, иначе сценарий пропускается.
- Сайт должен получать вебхуки LiveKit: стенд шлёт их на порты 3000 и 3100–3119. Другой
  порт добавьте в `APP_PORTS` стенда (`restart` делает это сам).
- Итог — таблица «прошло / упало» и код выхода; снимки при сбое и `report.json` — в
  `.tmp/e2e/<время>/`.

## Аналитика (PostHog)

Без `NEXT_PUBLIC_POSTHOG_KEY` / `POSTHOG_KEY` аналитика просто отключается. 
Снимок в Markdown: `npm run analytics:export` (за 30 дней) или
`npm run analytics:export -- 7` (за 7 дней). Нужны `POSTHOG_PERSONAL_API_KEY`,
`POSTHOG_PROJECT_ID` и `POSTHOG_HOST` в `.env.local`.
